# Pi Chat feature coverage

This checklist tracks implemented and pending product capabilities as of 29 October 2026. `[~]` means a partial implementation; `[ ]` means not implemented.

- [x] Use Pi's SDK and the user's existing Pi configuration, credentials, extensions, skills, prompt templates, and workspace session files; request trust before loading project-local Pi resources.
- [x] Pick an available model before the first prompt; show provider, context-window size, and image support.
- [x] Set the current model as Pi's global default for new sessions through an explicit model-control action.
- [x] Search models by provider, name, ID, or vision support; refresh manually and watch `models.json` for updates. Open the model picker or a supported thinking-level picker from the VS Code Command Palette.
- [x] Limit model cycling to a session-only ordered scope, load saved `enabledModels` patterns from Pi settings, and save an explicit scope back to global Pi settings; cycle to the next available model from the composer.
- [x] Choose a thinking level supported by the selected model.
- [x] Save, rename, remove, reorder, and use model/thinking presets; optionally choose a workspace default preset for new chats, falling back to Pi's configured model if it is unavailable.
- [~] OAuth/API-key sign-in through Pi's SDK; guided custom endpoint setup supports six built-in API formats plus API identifiers registered by loaded Pi extensions, with optional keys stored in VS Code SecretStorage and referenced from `models.json` through a Pi runtime variable. Manual catalog refresh remains available; automatic startup refresh is opt-in, requires an explicit warning confirmation, and is skipped in Pi offline mode. Provider account quota/balance are unavailable.
- [~] Show cumulative tokens and cost for the active session from Pi's recorded usage; provider account quota and balance are unavailable.
- [~] In-app Pi controls for automatic retry, automatic compaction, cache warming, and Pi startup network mode; Pi's configuration folder can be changed with a machine-scoped setting and folder picker. A per-workspace picker enables or excludes up to 500 discovered instruction files; `piChat.context.disableFiles` can suppress the full context-file loader, including configured and workspace `AGENTS.md` and `CLAUDE.md` files. Both choices apply after restarting Pi. Manage up to 32 uppercase custom runtime variables through VS Code SecretStorage (8,192 characters total); values are hidden during entry, excluded from diagnostics, and passed to Pi, its tools, and loaded extensions only after a manual runtime restart. Process-loader and runtime-control names are blocked. An OS sandbox remains unavailable.
- [~] Settings open the extension's searchable VS Code settings and Pi's `settings.json`. In-chat Pi controls cover queue delivery modes, thinking visibility, cache-miss notices, sharing destination, the default reasoning level for new sessions, provider transport, image resize/blocking, model defaults, automatic compaction/retry, startup networking, cache warming, and Pi install/update telemetry; advanced Pi-specific settings must still be edited in the file.

## Explicit scope and review notes

- Voice dictation is excluded at the user's request.
- All-workspace session search is opt-in; opening a result from another folder requires confirmation and starts that session in the folder's own VS Code window.
- Remote phone access is out of scope.
- Direct shell execution from the composer is unimplemented because automatic security review rejected adding that command-execution path.
- Pi tool calls use the user's current Pi permissions; narrower tool sets are available in the extension.
